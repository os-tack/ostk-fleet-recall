## What this receipt is not

- It is **not** evidence of an AWS deployment. Nothing in this wave was applied
  to a cloud environment, and no Terraform was applied.
- It is **not** evidence of a running system. Every module this wave added
  compiles into the library and is constructed only by its own tests. No
  binary, no serving path, and no scheduler or daemon reaches any connector,
  projector, or coverage runtime. `src/lib.rs` declares the modules; nothing
  else in `src/bin/`, `src/main.rs`, `src/service.rs`, or `src/application.rs`
  names them.
- It is **not** evidence of remote ingress. Both connectors read local
  material — a local directory of agent-transcript JSONL, and a local git
  object store through read-only `git` subprocesses. There is no webhook, no
  transport queue, no remote connector cursor, no acknowledgement protocol, and
  no dead-letter path for a remote delivery. That is stage 7.
- It is **not** evidence of an observer runtime, normative activation, or a
  discrepancy ledger (stage 6), and not evidence of any provider-verified PR,
  CI, artifact, or deployment relation (stage 8). No such module was added.
- The dense recall tier is **not** backed by a production embedding service.
  `EmbeddingProvider` is a trait with exactly two implementations in the whole
  repository, both named `FixtureProvider`, both inside
  `tests/recall_projection_live.rs` and `tests/visibility_live.rs`. The proofs
  drive it deterministically, including a provider outage and a degenerate
  all-zero vector; no network call to any model is made or implied.
- The two new publication-plane views are **not** granted to the deployed
  publication reader. That grant is a deployment action and it has not been
  performed. `fleet_publication_reader` still holds `SELECT` on exactly the
  same eight tables named in the Wave 0/1 receipt. The grant statements are
  generated by `projectors::publication_plane_grant_statements` and are applied
  only inside `tests/visibility_live.rs`.
- The Docker parity lanes remain **secondary**, exactly as the Wave 0/1 receipt
  states. The authoritative connected lane is
  `deploy/cockroach/tests/registry-activation-cli.sh` against the official
  CockroachDB `v26.2.3` binary.

Unlike the Wave 0/1 receipt, this one **does** cite CI; see "Proofs run".

## What was reviewed, and what was not

This is the honest difference from Wave 0/1. That receipt carried a reviewer
verdict per workstream. **This one cannot: the wave records no per-item
reviewer verdict.** All seven Wave-2 item records
(`.fleet-recall/fleet/items/W2-*.json`) carry an empty `blockers` list and an
empty `observations` list. What actually caught defects in this wave was the
merge gate on the cherry-picked union, and then running the proofs for real:

- **Two migration-number collisions were caught only by the merge gate**, not
  by any per-item review. W2-BODY (0019) and W2-COVER-RT (0020) were built in
  parallel and arrived as one fused migrator entry (`14f7296`). W2-PROJ and
  W2-TRANS both claimed 0021; the transcript connector was renumbered to 0022
  (`311e5ce`). Neither item's own gates could see the conflict, because neither
  item contained the other's file.
- **Three connected proof suites were never running in CI at all.** The
  official-binary lane discovers connected tests with the regex
  `^live_[a-z0-9_]+: test$` over `cargo test --test <bin> -- --list`.
  `tests/body_projection_live.rs`, `tests/recall_projection_live.rs`, and
  `tests/visibility_live.rs` named their `#[tokio::test]` functions without the
  `live_` prefix, so 23 database-gated tests could never be discovered and had
  never executed. This was found at wave close and fixed in `e7906b0`.
- **Running them for real then exposed a genuine bug.** `visibility_live.rs`
  creates a login role to prove the publication plane has no SQL path to a
  private row, and left that role on the cluster. CockroachDB v26.2 seeds a
  database-level PUBLIC `EXECUTE` routine default under every role, so the
  leaked role appeared as an extra grantor row and broke the lane's exact
  PUBLIC routine-default audit. Fixed in `1d6a02b` by giving the probe a
  unique name and tearing it down, the convention
  `tests/evidence_ledger_live.rs` and `tests/registry_witness_live.rs` already
  followed.
- **Five assertions had gone stale against the Wave-1 migration head.** Four
  lane assertions hard-coded head 18 (the exact successful migration prefix,
  the history after exact index replay, and two failed-migration-12 probes);
  they now derive the head from `migrations/`, with a floor guarding an empty
  directory (`aef7954`). One library test in `src/store/cockroach.rs` inserted
  a fake history row at version 19 to probe unknown-migration rejection, which
  was safe when written and collided with real migration 0019 in this wave; it
  now derives the probe version as `max(embedded version) + 1` (`af4a37d`).

## What the security boundary proofs actually assert

Recorded here because "publication plane" is the claim most easily overstated.

- A recall projection row is publication-safe only when the accepted evidence
  event's visibility class and publication class are *both* the approved value
  **and** the governed content's protection domain equals the event's own
  authenticated project namespace. The classification function is total and
  returns private for every other combination, so a future enum variant can
  only ever make a row more private.
- That decision is held closed in three independent places: the
  `visibility_class` column defaults to `private`, so an INSERT that omits it
  cannot be public by omission; a database `CHECK` refuses a publication-safe
  row whose recorded evidence classes are not the approved pair; and the
  predicate is compared inside the lexical and dense SQL ahead of ranking, so
  count, offset, and ranking probes see the same boundary a plain query does.
- The publication plane reads two fixed filtered views and is granted nothing
  on the base tables, which puts a private row outside its privilege set rather
  than merely outside its answers. `live_the_real_publication_role_has_no_sql_path_to_a_private_row`
  asserts this as the real role, not as a simulated one.
- Both connectors bind scope from the credential-bound witness, not from their
  input. `live_a_candidate_selecting_a_foreign_scope_is_refused_closed` and
  `live_a_cross_tenant_candidate_is_rejected_closed_when_configured` are the
  negative cases; `live_a_connector_outside_the_active_package_is_refused_closed`
  covers a connector absent from the active package.
- The transcript connector redacts before anything durable exists, and a turn
  whose post-redaction rescan still matches a secret shape is withheld
  entirely — no row is built for a later stage to leak.
  `live_a_planted_secret_never_reaches_the_outbox_the_ledger_or_the_content_store`
  is the end-to-end assertion.
