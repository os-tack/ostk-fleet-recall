Isolation and cleanup
---------------------

The fixture database was separate from the production database. The production
database was neither queried nor modified by this proof. After the plans were
captured, the disposable database was dropped and the temporary workstation
network rule was removed.

Method
------

The proof used the exact project-scoped vector, source-scoped vector, and
selective lexical SQL shapes defined in src/store/cockroach.rs. Parameters were
bound with SQLx, as they are in the application. Database, tenant, and project
identities below are publication-safe placeholders.

Project-scoped vector query shape
---------------------------------

SELECT chunk_id, (embedding <=> $3::VECTOR(512))::FLOAT4 AS score
FROM memory_chunks
WHERE tenant_id = $1
  AND project = $2
ORDER BY embedding <=> $3::VECTOR(512)
LIMIT $4

Selective lexical query shape
-----------------------------

SELECT chunk_id,
       ts_rank(search_document, plainto_tsquery('english', $3))::FLOAT4 AS score
FROM memory_chunks
WHERE tenant_id = $1
  AND project = $2
  AND search_document @@ plainto_tsquery('english', $3)
  AND ($4::STRING IS NULL OR source = $4)
  AND ($5::TIMESTAMPTZ IS NULL OR source_timestamp >= $5)
  AND ($6::TIMESTAMPTZ IS NULL OR source_timestamp < $6)
ORDER BY score DESC, chunk_id
LIMIT $7

Statistics visibility caveat
----------------------------

In the original long-lived test connection, the lexical EXPLAIN ran immediately
after ANALYZE and briefly saw the pre-load zero-row automatic statistics; it
selected the primary index. A fresh session then saw the completed 10,001-row
statistics and selected memory_chunks_lexical_idx as shown above. Session-only
checks with canary_stats_mode forced to both stable and canary also selected the
same lexical index and passed all three assertions. The two vector plans used
their intended C-SPANN indexes before and after the statistics refresh.
