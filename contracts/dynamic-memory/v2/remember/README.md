# Canonical remember v2 contract vectors

These fixtures freeze the contract-only boundary for deliberate claim assertions. Every `.jsonl` file contains one record plus exactly one repository-framing LF; the LF is excluded from contract digests. None of the fixture scope, head, actor, registry reference, resource URI, or support ID carries runtime authority.

`RememberIngressCandidateV2` contains only public assertions: an asserted subject URI; exact identity-recipe, predicate, applicability, and admission-rule references; a closed assertion kind; exact authored text; typed proposition data; an effective interval; a requested admission basis; and cited accepted evidence IDs. It cannot supply profile, scope, registry head, actor, event kind, fingerprint, receipt state, or append coordinates. Every ingress reference, URI, basis, and support ID is untrusted. In particular, `admission_rule` is compare-only: the server must route to one unique active rule from trusted scope, predicate, and basis, then require the asserted reference to equal it.

The positive predicate and admission artifacts are full `RegistryEntryV1` preimages, not free bodies. They use the existing `predicate_schema` and `authority_rule` entry kinds with exact v2 schema IDs. `StructurallyResolvedRememberContractsV2::from_registry_entries` derives references from the full entry digests, decodes exact typed bodies, and cross-closes IDs, versions, predicate/evaluator dependencies, and modalities. This remains authority-free: active-package membership and unique server routing must be proven separately. Each entry's positive and negative vector digest points to a checked-in canonical semantic case manifest; those manifests do not reference entry bytes and therefore introduce no digest cycle.

`RememberPredicateSchemaV2` closes the subject identity, every applicability dimension's resource identity, resource-valued claim identity, comparator, modalities, evaluator, absence/coverage semantics, and publication/sensitivity defaults. A URI resource-kind label matching a constraint entry ID is only a structural check. Runtime admission must resolve the exact active `ResourceKindSchema` and `IdentityRecipe` bodies, prove the recipe embeds the required kind and identity form, obtain a trusted canonical-locator witness, and rederive the subject, every applicability URI, and any resource-valued claim. Payload-selected recipes or URI labels are never identity proof.

`RememberAdmissionRuleV2` closes assertion kinds, basis semantics, effective-time policy, text ceiling, and exact classifier, redaction, retention, and publication roots. Active closure must resolve those governance bodies and cross-check the predicate's publication/sensitivity defaults against them. All payload authority switches are false, including actor, scope, head, admission rule, and admission outcome; text limits may be stricter than, but never exceed, the 100,000-byte hard contract bound.

The authored text field is named `assertion_text_utf8_hex_chunks` because the frozen canonical JSON profile rejects control scalars inside JSON strings and caps one string at 65,536 bytes. Its deterministic array of lowercase-hex chunks preserves up to 100,000 exact NFC UTF-8 bytes, including LF, TAB, leading indentation, trailing spaces, and a final LF, without trimming or newline normalization. Every non-final chunk represents exactly 32,768 raw bytes, so the same text has one wire form; whitespace-only text, CR, NUL, noncharacters, private-use scalars, BOM, and other controls are rejected. Predicate string values remain ordinary canonical, trimmed, control-free strings.

`SemanticClaimV2` binds the frozen runtime profile, trusted scope, ABA-safe active-head coordinates, canonical subject, exact interpretation references, closed assertion kind, modality, polarity, typed value, concrete applicability, and exact effective interval. It accepts only `decision`, `fact`, `constraint`, `preference`, and `procedure`. Legacy `observation` belongs in evidence v2; free-form `note` and `open_question` require distinct contracts and are not silently coerced.

There is no float, null, arbitrary JSON, generic array/object, numeric actor ID, numeric claim ID, or numeric support ID. Values are explicitly tagged as boolean, canonical decimal, contract ID, resource URI, SHA-256 digest, canonical string, or a canonical string set strictly sorted and unique by NFC UTF-8 bytes.

The claim fingerprint is:

`SHA-256("ostk-remember-semantic-claim-v2" || 0x00 || canonical_semantic_claim_bytes)`

Authored wording, actor, admission rule/basis, and cited support are attestation semantics: they are excluded from the shared claim fingerprint but included in `RememberAcceptedStatementV2` and therefore in its accepted-event ID under the existing `ostk-accepted-event-v1` domain. The frozen positive rule is actor-only and admits `attested` or `intended` assertions from any authenticated principal in the trusted project scope; it intentionally has no narrower actor-allowlist policy. Actor assertions may cite zero events because the authenticated attestation is itself declared evidence.

Registered-observer and activated-normative basis shapes are reserved structural contracts, not usable append paths in v2: both enable flags are required to remain false. Registered observer remains unavailable until a typed, head-bound observer-result/run event commits exact observer admission, predicate/evaluator, emitted claim/output, executable artifact/configuration, scope, full registry head, and coverage witness. Normative binding remains unavailable until a durable v2 witness binds the full ABA-safe registry head. Merely citing an `AcceptedEventId`, an observer schema label, or the current v1 normative receipt cannot enable either path.

All potentially competing assertions share a logical consistency stream derived as:

`SHA-256("ostk-remember-claim-coordinate-v2" || 0x00 || canonical_claim_coordinate_bytes)`

with `{family: "claim", key_digest: claim_coordinate_id}`. The coordinate retains frozen profile, trusted scope, subject/recipe, predicate, evaluator, and concrete applicability. It deliberately omits value, polarity, modality, interval, actor, support, and the entire registry-head binding so contradictory or overlapping claims—and claims crossing a registry cutover without an interpretation-reference change—cannot escape to different logical streams. Epoch, shard, offset, receipt clocks, and chain digests remain physical and are absent from accepted-event identity.

The public accepted statement is still only structural bytes. Future append code must consume an opaque admitted typestate produced from one active-registry, trusted-scope, locator/identity, actor, support, governance, and server-routed admission-rule witness in the same transaction. This first seam records immutable assertions only. Correction, supersession, and retraction require separate event kinds naming an exact prior `AcceptedEventId` and proving retirement authority; public record ingress cannot acquire that authority by carrying a predecessor field.

At the `event_first` cutover, the admitted accepted event must be durable before or atomically with its projections, and the legacy `ClaimInput` path must no longer write directly. Existing tenant-wide idempotency keys remain reserved: an exact imported receipt replay is read-only, while different canonical bytes under the same key collide. Legacy `memory_events` UUIDs are opaque imported audit provenance, never accepted-event IDs.

The adversarial records prove that floating values, arbitrary JSON, numeric support IDs, ingress authority fields, statement physical fields, broken resource constraints, unknown publication defaults, open observer rules, duplicate logical basis keys, impossible basis modalities, and payload-selected admission authority fail closed. Rust tests raw-pin every positive, manifest, and negative artifact as well as ingress, semantic claim, accepted statement, and aggregate suite. The two remember prefixes are closed shared `DigestDomain` variants. Changing any canonical record, prefix, fixed event kind, expected digest, or ordering rule is a contract-version change.
